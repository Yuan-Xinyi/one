## 3. 本次讨论已定的决策

以下为已经拍板的决定，**不要重新论证或提议回退**。

### 决策一：定位为运动学轨迹生成，不是在线控制

论文实际做的是速度级冗余度解析后前向积分，得到一条关节轨迹；评测是 10,000 个事先给定、几何完全已知的任务，无真实测量反馈、无扰动。因此：

- 标题里的 "Hybrid Null-Space Control" 改成生成/冗余度解析的措辞（现标题内部自相矛盾：前半是 generation，后半是 control）。
- 实验节明确写清全部为运动学仿真，claim 限定在 kinematic feasibility。
- **补时间参数化实验**：对生成的关节轨迹做时间参数化（导师批注提过 Ruckig），报告速度、加速度是否落在 FR3 限内，以及切换处的跳变是否被吸收。这一个实验同时回应 R1 的切换稳定性和 R2 的动力学质疑，成本远低于真机或完整动力学。
- 代价：需要正面回答「为什么不用现成的轨迹优化离线解」。答案与主线论点同源，见决策二。

> **2026-08-03 实测：投稿版不具备叫 control 的条件。** 脚本 `Yuan/system_eval/control_audit.py`，128 个直线任务、混合控制器。判据不是「输不输出关节速度」（它确实输出，而且 4–5 万个在线步里 0.000% 超出 FR3 关节速度限值），而是能否抑制扰动、能否容忍被控对象与模型不一致。
>
> | 判据 | k_lateral = 0（投稿版） | k_lateral = 5 |
> |---|---|---|
> | 5 mm 横向扰动后的路径误差 | 5.79 → 8.95 mm（**发散**），每步 1.014 | 5.09 → 0.67 mm，每步 0.763（设计值 exp(−k·dt) = 0.779） |
> | ±10% 逐关节执行器增益误差下的弧长 | **0.766** | 1.000 |
> | 同上，横向终止占比 | 12.5% → **64.8%** | 8.6% → 7.8% |
>
> 投稿版两条全不过：它按自己的模型前向积分，任务速度是纯前馈，没有任何机制纠正笛卡尔误差，所以任何持续偏差都无界累积。加上 k_lateral 之后两条都过，且抑制速率与设计增益吻合到 2%。
>
> **但即便如此仍不宜在系统层面叫 control**：(1) 环只闭在**横向**，沿路径方向按设计开环（目标是弧长而非时间参数化轨迹）；(2) 环闭在积分出来的 q 上而非测量值，测试 C 只是证明这条律**能**扛住模型失配，论文并没有真的把它接到任何非自身积分器的对象上。
>
> **可操作结论**：若改稿里要声称任何反馈性质，必须把 k_lateral 纳入方法本身并重跑主表——否则是拿新配置的性质去背书旧配置的结果。代价很小：κ=0 上平均弧长 0.5025 → 0.5042（+0.3%），横向终止 9.6% → 7.8%。

### 决策二：主线重新定位到分支结构

**论文现在把创新点押在了较弱的一半上。** 真正的核心不是 hybrid 控制器，而是「关节极限把自运动流形切成不连通分支、可达路径长度主要由起始落在哪个分支决定」这个运动学洞察，以及由此导出的、用条件生成模型做分支选择的方法。

支持证据（全部来自论文自己的表）：

| 对比 | 数值（ratio to reference） | 贡献 |
|---|---|---|
| 固定 hybrid 控制器，换种子（Table 2） | q_jl 77.1 / q_μ 77.6 → DP 90.6 | **+13.0 pp** |
| 固定 classical 控制器，换种子（Table 2） | q_jl 58.6 / q_μ 61.3 → DP 76.1 | **+14.8 pp** |
| 固定 DP 种子，RL → Hybrid（Table 1） | 85.0 → 90.6 | **+5.6 pp** |

即种子选择模块的贡献是切换机制的两到三倍。这与 2026-07-03 尾部分析结论一致：paper metric 损失的 85~90% 来自 DP 种子选择（cone deaths，非 jl）。

论证强度也更高：零空间梯度上升在零空间内走连续路径，构造上跨不过关节极限，只能停留在起始分支——这是近乎可证明的论断。同一论证还能回答「为什么不能用轨迹优化替代」：目标函数是存活步数、不连续，且梯度类优化只能停在被初始化的那个分支里。

新的三层骨架：

1. 瓶颈在自运动流形的分支结构（洞察）
2. 条件生成模型跨分支选起点（主要贡献）
3. 混合零空间解析在分支边缘维持运动（支撑组件）
4. 全部 claim 限定在运动学可行性内

### 决策三：曲线扩展的定义方式

定义**不改**，改的是路径的给定方式：从「一条有限曲线」改成「可无限延展的曲线 + 延展规则」。弧长仍是目标量，因为仍不封顶。

用内蕴方式描述：曲线由曲率沿弧长的函数 κ(s) 确定，直线是 κ ≡ 0。于是：

> **Extreme motion generation**：给定一条由延展规则确定的、原则上无界的笛卡尔路径，以及沿路径的工具朝向约束，求初始关节构型和冗余度解析策略，使得在任一安全约束被违反之前所走过的弧长最大。

与现定义相比只把「直线」换成「由延展规则给定的无界路径」，弧长、终止条件、三个约束一字不改。

**第一步扩展选常曲率圆弧**，理由：条件向量只加一个标量（c = [p₀, d, n, κ] ∈ R¹⁰）；κ=0 精确退化回现有结果，扩展正确性可自检（重训后先验证 κ=0 能复现 90.6%）；曲率是连续参数，可扫出退化曲线。往复扫描（raster）作为工业形态展示更好，但作为泛化性的测量工具分辨率不如圆弧。

> **2026-08-03 实测补充**：κ 本身不是控制变量，**转过的总角度 φ₀ = ℓ_ref(0)·|κ| 才是**（见第 6 节 2×2 归因协议下的批注）。这不推翻「先做常曲率圆弧」的决定——圆弧仍是扫出这条曲线最省的载体——但影响条件向量该怎么加：单纯把 κ 拼进 c 会让模型在「弯但走不远」和「不太弯但走得远」这两类任务上学到冲突的标签，而它们的 φ 其实相同。可考虑同时喂 κ，让网络自己从 p₀、d、n、κ 去推 φ；或直接在损失/特征上体现 φ。这一条在重训前需要定。

**不用改的东西**：reference length 的定义（若干种子候选里最长的 rollout）与路径形状无关；ratio to reference 指标形式不变；切换规则 ρ(q) 只依赖关节构型，路径无关（这点值得在改稿里明说，因为它正是评审攻击最集中的组件）。

### 决策四：三个坑的处理方案

用户提出三个技术坑，均成立，处理方案已收敛到一致的设计。

**坑三（影响最大）：工具姿态约束在 κ≠0 后分叉。**
关键是保住零空间维数。现在朝向是不等式（锥），不占任务自由度，任务 3 维、零空间 4 维。若改成等式约束，任务变 5 维、零空间掉到 2 维；再定死绕工具轴转动，零空间只剩 1 维——方法的前提（有丰富冗余可利用）就被掏空了。

方案：采用 R_tool(s) = R_frame(s) Q(s) 参数化，但 **Q(s) 必须带容差、保持不等式形式**。即把固定的 n 换成沿路径变化的参考方向 n_ref(s)，约束形式 arccos(z(q)ᵀ n_ref(s)) ≤ θ_max 一字不改。

R_frame 由**物理过程**决定而非曲线微分几何：焊接的工具姿态本就用两个角度规定（相对工件表面、相对行进方向），所以物理上正确的标架是 (T, n_surface × T, n_surface)。它不依赖曲线的 T′，任何正则曲线上都良定义。

**坑一：Frenet 标架在 κ=0 处坏掉（N 无定义、过零翻转、τ 发散）。**
诊断正确，但对眼下这一步不咬人：平面内常曲率圆弧的场景中 n 是给定且固定的，曲线法向可直接取 n × T，κ=0 处良定义、过零不翻转（平面曲线的 Bishop 标架本就等于 (T, n×T, n) 差一个常值转动）。现有条件向量显式携带 n 而非从曲线导出标架，**已经是 Bishop 式的，不需返工**。走到空间曲线/非平面时，用两个自然曲率 (k₁, k₂) 替代 (κ, τ)，条件向量顺势扩为 [p₀, d, n, k₁, k₂]。处理原则：现在不碰，但设计上从一开始不依赖 Frenet。

**坑二：直线不是最容易的一档，等弧长下它离起点最远，工作空间边界对它约束最紧。**
成立，但**这不只是测量注意事项，而是对论文中心论点的判决性检验**。论文主张包络不是紧约束（Introduction 明确写了终止发生在末端远未接近可达边缘之前，瓶颈是关节极限和锥约束）。于是曲率扫描的结果有两种含义：

- 弧长随 |κ| 显著增长 → 空间延展度才是真约束，中心论点被削弱；
- 弧长随 |κ| 持平或下降（绕圈时关节漂移推向极限，即冗余度解析的不可重复性）→ 正面支持中心论点。

**建议尽早做这个检验，因为结论会影响论文中心论点怎么写；若结果不利，重新定位方案需比现在更保守。**

> **2026-08-03 已做完，结果有利。** 完整结果见 `Yuan/system_eval/runs/curvature_scan/RESULT_ZH.md`。要点：R ≥ 0.5 m 上可达弧长对曲率不敏感（容量比值中位 0.97–1.03），终止发生在末端距可达边界中位 0.27 m 处、仅 8.5% 落在 5 cm 以内 —— **中心论点成立，且可以改成带数字的陈述**。只有 R = 0.25 m 上容量中位升到 1.30，但它依赖控制器（混合 1.30 / 经典 1.04）且与「离边界多近」反相关（贴边界层增益最小），因此不是包络效应；分布还是双峰的（59% 变好、36% 变差到 0.9 以下），必须如实报告。难度分桶必须固定在 κ=0：|κ|=4 时按 ℓ_ref(0) 分的三层容量比是 1.63 / 1.66 / 0.82。

测量本身已被现有指标保护：ratio to reference 的分母是同一任务、同一 κ 下算出的，是 κ 内部比较，不跨 κ。**真正必须修的是难度分桶**——现在 Easy/Medium/Difficult 按绝对 ℓ_ref 划分，混入不同曲率后小半径圆弧会因累积弧长长而被系统性划进 Easy。需改为在每个 κ 内部分桶，或换用对曲率不敏感的划分依据。

- 进度项 `delta_progress = ((p_new - p) * self.line_dir).sum(-1)`（:394）：逐步位移在方向上的投影，切向逐步更新后自然变成弧长进度，**无需修改**。
- 观测 31 维中**不含任何曲率信息，也无前瞻**。

## 5. 可直接回应评审、无需新实验的点

- **R2 说 hybrid 增益在 Difficult 上消失**：他用的是绝对路径长度差（Easy +0.07 m、Difficult +0.01 m），而绝对差天然随 reference length 缩放（Difficult 桶的定义就是 ℓ_ref < 0.45 m）。换成论文自己的 ratio 指标，hybrid 对 RL 的增益是 Easy +6.7 pp、Medium +5.1 pp、Difficult +5.2 pp，**三桶基本均匀，不存在消失**。但需同时承认论文表述漏洞：难度分桶（按 ℓ_ref）不等于「执行中离边界的远近」。彻底的做法是补一个按机制条件化的分析——按每条轨迹在边界壳层（ρ ≥ τ_enter）内度过的步数比例分组，展示 hybrid 对 RL 的增益随之增长。
- **R3 说动作 4 维与任务 5 维矛盾**：误读。工具朝向是锥形容差的**不等式**约束（Eq. 4），不是跟踪平面法向的等式约束，故主任务只有 3 维位置，7−3=4 维零空间，自洽。论文 4.2 说了「only the 3-DoF end-effector position must be precisely tracked」但没挑明「朝向是不等式约束、不占任务自由度」。改写一两句即可。
- **R3 问经典基线权重怎么调的**：Table 3 就是 39 组权重的完整扫描，默认值 (0.8, 0.4, 0.2) 取自扫描最优（与 2026-05-30 在 10k 集上的网格扫描结论一致），即基线是调到最优后再被比较的。正文明确写出来即可。
- **R3 问 RL 的 foresight 来自哪里**：策略虽为逐步反应式，但 PPO 以折扣回报为目标训练，价值函数把未来终止风险折算进当前动作选择；而经典控制器的次级目标是逐步瞬时优化，无任何跨步目标。需在 Introduction/4.2 写明，避免 foresight 读起来像显式规划。
- **R3 问跟踪误差**：位置误差被 ε_pos 硬约束，实际误差统计应可从缓存的评测数据直接算出，加一列或一小段即可，同时回应 R2 的「更长行程是否以精度为代价」。
- **R2 说离线规划器已能处理**：评审自己也承认 reachability-map 那条线与本文是互补而非替代。回应方式是明确 base placement 决定工作空间包络、本文解决给定包络后执行中如何延迟触碰安全边界，两者正交；同一论证的另一面即「为什么梯度类轨迹优化不能替代」（见决策二）。

### 2×2 归因协议

做曲线实验时用论文现成的 seed-by-controller 协议做分解：{直线训练的种子, 重新打分的种子} × {直线训练的策略, 经典控制器}，把退化归因到种子还是策略上。

**预判**：策略侧退化较小（观测里无任何编码「路径是直的」的量，训练时 d、n 已在工作范围内广泛采样，单步 (q, d_t, n_t) 大概率在分布内；真正失配在价值函数——它学的是「沿当前方向一直走能活多久」，故退化应随「可达长度 / 曲率半径」增长）。种子侧退化更大（条件向量 c 是直线描述子，标签用直线 rollout 打分；且种子是一次性全局决策，无逐步纠正机会）。若测出确实如此，重训种子就是目标明确的改进项。

> **2026-08-03 实测：预判全部成立。** 逐任务配对，R = 0.25 m 上种子侧掉 14.2 pp、控制器侧掉 5.7 pp（纯 RL 6.1 pp，经典 2.1 pp）——种子侧是控制器侧的 2.5 倍。经典控制器几乎不动，符合它与路径形状无关；纯 RL 多掉的部分与价值函数的失配一致。
> 连预判里那句「退化应随可达长度 / 曲率半径增长」也被证实，而且是这次最有价值的发现：**控制变量是转过的总角度 φ₀ = ℓ_ref(0)·|κ|，不是曲率**。按 φ₀ 分桶，不同 κ 的点塌到同一条曲线（0–20° 时 1.000，60–90° 时 0.980，130–180° 时 0.854，180–260° 时 0.837），每桶都混着 3–4 个不同的 |κ| 且给出同一个值。R = 0.25 m 之所以特殊只是因为手臂在那里活得久、转过约 190°。
> **口径警告**：种子侧与控制器侧的对比必须逐任务配对；跨 κ 直接比中位数会把参与统计的任务总体变化误算成退化（我第一版就是这么错的，一度得出「策略侧退化不比种子侧小」的相反结论）。

**非平面比曲线更难**：法向逐步变化使锥约束中心移动，工具须持续重定向、持续消耗冗余度。直接后果是 Table 3 的 Note 1（「锥门 g(θ) 很少激活，故 k_θ 影响很小」）不再成立，k_θ 会变成主导权重，而现在的 0.2 恰是在锥门几乎不触发的条件下调出来的。更要紧的是按 2026-07-03 尾部分析，现有损失本就主要来自锥违反而非关节极限，非平面正好加剧这个已占主导的失效模式。难度排序：平面缓弯基本可用 < 平面急弯明显退化 < 非平面最难。
