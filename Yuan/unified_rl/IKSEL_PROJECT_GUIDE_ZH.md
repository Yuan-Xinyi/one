# 从零理解本项目:极限运动生成(Extreme Motion Generation)

**读者对象**:了解基本机器人/机器学习概念,但没有本项目背景的入门者。
**读完你应该能回答**:这个系统每一步在做什么、为什么这样设计能奏效、哪些看似合理的做法实际上是错的。

**一句话定位**:本项目研究 **extreme motion generation(极限运动生成)**——让固定基座机械臂沿指定轨迹走出尽可能长的路径,在不加大机械臂、不挪底座的前提下扩大单次装夹的有效工作范围。整个故事有两级:**执行级**(混合零空间控制:内域 RL 有远见、近边界经典控制器稳)负责"走的过程中不断推迟撞上安全边界";**初始化级**(查表枚举 + 回报监督选择)负责"从正确的分支起步"。起手姿势的选择是故事的一部分,不是全部——两级缺一不可。

---

## 第一部分:问题是什么

### 1.1 任务

一台 7 关节的 Franka 机械臂,末端装一支笔。给定:

- 笔尖的起始位置 p₀;
- 一条从 p₀ 出发的目标射线(方向 d);
- 笔的朝向要求:笔杆必须保持在某个参考方向 n 的 30° 锥内。

机器人要让笔尖沿射线尽可能**走远**。走的过程中任何时刻违反约束——关节到极限、笔杆出锥、笔尖偏离射线超过容差、碰撞——运动立即终止。**成绩就是终止前沿射线前进的米数**(全文叫 progress 或路径长度)。

### 1.2 为什么这个问题不平凡:起手姿势的"分支结构"

7 个关节去完成一个只约束 5~6 个自由度的任务,意味着**冗余**:同一个笔尖位置+合规朝向,存在很多种关节摆法。这些摆法不是连续一片的——关节极限把它们切成了**互不连通的分支**(专业名词:自运动流形的分支)。想象同一个握笔位置,你可以肘朝上、肘朝下、手腕内拧或外翻——每种是一个分支,分支之间无法在不放开笔的情况下互相转换。

关键事实(实测):**同一个任务,最好分支和最差分支的最终成绩差,中位数是 472 毫米**——而任务平均成绩才 550 毫米左右。也就是说,**运动还没开始,结局就已经大半注定了**。

### 1.3 为什么难:三个互相锁死的性质

1. **决定性**:选错分支,后面的控制器再好也救不回来;
2. **延迟显现**:分支的好坏,要走到轨迹后段(笔杆慢慢逼近锥边界)才暴露。开局那一刻,好分支和坏分支在任何"当下能算的量"上都长得差不多;
3. **不许试错**:部署时每个任务只允许真实执行一次。想"每个分支都试跑一下再挑"?一次试跑的成本几乎等于跑完全程(平均轨迹只有 ~55 步),试跑=作弊。

所以问题本质是:**在不执行的前提下,预判哪个起手姿势能活到最后。**

## 第二部分:系统怎么工作(五步流水线)

```
【离线,一次性】 建姿势字典(CVT 表)
        ↓
【在线】① 锥内采 32 个笔杆方向
        ② 每个方向查字典 → 雅可比重排 → 取最优种子
        ③ 数值精修(失败就换个差别大的种子重试,至多 4 次)
        ④ 挑选器(神经网络)从 ~29 个候选里挑 1 个
        ⑤ 混合控制器执行一次 → 出成绩
```

### 步骤 0(离线):建姿势字典

在 7 维关节空间里,用 **CVT 采样**(Centroidal Voronoi Tessellation)生成 201,600 个**均匀铺开**的关节姿势——想象在一个 7 维盒子里撒 20 万个点,并且让它们彼此保持距离、不结团不留洞。每个点算一次正运动学,存下:关节角 q、笔尖位置、笔杆方向、雅可比伪逆 J⁺。全部塞进一棵 KD-tree(一种支持"查最近邻"的数据结构,20 万条查询只要 0.1 毫秒级)。

**这张表与任务无关、与训练无关、10 分钟建完、永久复用。** 这是本项目前作 IKSel 求解器的核心资产,原样继承。

### 步骤 ①:锥内采方向

任务只说"笔杆在 30° 锥内即可",没规定具体朝向。我们在锥内均匀采 32 个方向(锥心算一个)。每个方向配上 p₀ 就是一个完整的目标位姿。**多样性从这里来**:不同的笔杆倾斜方式,天然对应流形上不同的区域。

### 步骤 ②:查字典 + 雅可比重排

每个目标位姿去 KD-tree 里查 200 个最近邻(键=笔尖位置÷5cm 拼上笔杆方向;除以 5cm 是让"位置差 5 厘米"和"朝向差约 57°"在距离里等价——位置被加权得很重,因为查出来的姿势必须能被数值迭代**拉到**精确目标上)。

然后是 IKSel 的招牌一步:**不按"位姿距离"排序,按"预计需要的关节调整量"排序**——用每条表项预存的 J⁺ 算 Δq = J⁺·(位姿差),取 ‖Δq‖ 最小的。为什么?位姿近≠好种子:两个位姿在空间里挨着,关节上可能隔着十万八千里(想想肘上肘下)。‖J⁺Δ‖ 小意味着这个种子在目标的"线性邻域"里,牛顿式迭代大概率几步收敛。

### 步骤 ③:精修 + 失败重洗

每个方向取排第一的种子,跑阻尼最小二乘(DLS)迭代把它精确拉到目标位姿上,然后过全套物理校验(关节极限、5mm 位置误差、锥、碰撞)。

**失败了怎么办?** 这是前作 IKSel 的另一个招牌:不是傻傻地试第二名(它多半和第一名在同一个死胡同里),而是把剩余候选按"**离已试过的种子最远**"重新排序再试——主动跳到另一个分支去。至多试 4 次。实测这一招把每方向成功率从 73% 拉到 **87.7%**。

32 个方向跑完,去重(关节空间 0.08 弧度内算同一个),平均剩 ~29 个真实、精确、横跨各分支的候选姿势。

### 步骤 ④:挑选器

29 选 1。每个候选算 45 维特征(控制器视角的初始观测 + 射线误差 + 可操作度 + 10 个沿任务方向的微分运动学量),丢进 5 个小网络组成的集成(每个网络看整个候选集合、输出每个候选的分数),平均分最高者当选。

**这个网络是怎么教出来的?训练时,把 20,000 个练习任务的每一个候选都真实执行到底,记下各自的最终成绩,用"完整成绩单"教网络排序。** 这是全系统唯一的学习组件,也是唯一必须用执行数据的地方。

### 步骤 ⑤:混合控制器执行

选定姿势后真实执行一次。控制器把每步的关节速度拆成"任务项(沿射线追踪)+零空间项(冗余怎么用)";零空间项在配置空间内部由 RL 策略给(有远见,会提前布局),贴近关节极限时切换给经典梯度控制器(短视但绝对稳),带迟滞防抖。

## 第三部分:机理——为什么每一环能奏效

这是本指南的核心。每个"为什么"都对应一组真实实验。

### 3.1 为什么查表+精修能替代 128 次穷举?(而且只花 1/3 的算力)

穷举的浪费在于**盲目**:128 次随机重启里,大部分尝试重复收敛到同几个大盆地,少数尝试落在没救的区域。查表的三个机制各治一处浪费:

- **CVT 均匀覆盖** → 每个分支附近都有表项,查询天然"每个分支来一票";
- **雅可比重排** → 只把算力花在"预计能收敛"的种子上(这是可以提前算的,因为收敛性由局部线性度决定,J⁺ 恰好度量它);
- **失败重洗** → 死胡同只进一次。

一个反直觉的实测教训:**表不能压缩**。把 20 万条聚类成 2 千个"代表",成绩掉 23mm——因为聚类中心是**平均值**,是不存在于流形上的人造姿势,做种子天然差。CVT 采样的点每个都是真实姿势,这是"采样"和"压缩"的本质区别。

### 3.2 为什么几何直觉挑不准,而"成绩单教学"能?

我们实测了所有能想到的几何评分(可操作度、离关节极限的距离、沿任务方向的线性化可走行程……):**全部比"闭眼选第一个能用的"还差**(捕获率 −23%)。原因回到 1.3 的"延迟显现":决定生死的是几十步之后笔杆出不出锥,而这取决于零空间运动的**累积**效果,不是开局的几何快照。

用完整成绩单监督后,同样 45 维特征、同样网络,捕获率到 **~67%**。信息不在特征里凭空出现——是**标签**把"未来"教给了网络:它学会了从开局快照**预测**运动学演化的走向。旁证:我们后来把"精确的运动学前瞻"(把每个候选沿控制场纯数学推演到撞约束为止)作为新特征加进去,**成绩一分没涨**——网络早已从一步量里自己内插出了这个前瞻。

### 3.3 为什么天花板是"大约三分之二",推不上去?

我们从三个独立方向攻击过这个天花板,全部失败,由此断定它是**信息论边界**而非工程欠账:

1. 加大网络、加长训练、换结构 → 平台不动;
2. 送上完美运动学前瞻 → 零增益(见 3.2);
3. 给每条表项挂上"它在原任务里的历史成绩"当先验 → 秩相关只有 0.089,零迁移。

剩下那 1/3 是什么?**RL 策略自己的行为偏差**。纯运动学推演平均只能走 0.27m,RL 实际走 0.415m——多出来的部分是策略"怎么花零空间"的个性化决策,它不服从任何固定的场,**只有真的执行才知道**。而执行恰恰是部署时买不起的。所以 2/3 是"部署前可知信息"的极限,我们把它测出来了(这本身是论文的一个贡献)。

### 3.4 为什么控制器不需要为新的起手分布做适配?

按"前后级要互相适配"的直觉(Sequential Dexterity 式),挑选器选出的新分支姿势应该让控制器重新训练适应。我们试了两轮(第二轮把续训工程做到位:critic 预热、零熵、紧信任域、四倍步数),**效果都是零**,而且训练奖励全程饱和在 0.99——控制器表示"这些状态我都会"。

机理:控制器的观测是**任务相对**的(不含绝对位置),又在 **10 万个随机任务**上训练过。在它眼中的状态空间里,"任务 A 的陌生分支"就是"训练时任务 B 的寻常状态"——分布漂移被观测设计提前吸收了。分层检验证实:哪怕挑选器选到离旧分布 4 弧度远的姿势,控制器从那里出发反而表现最好。这条规律在三种不同的候选机制上独立复现了三次。

**工程含义**:整条流水线里,只有挑选器需要训练;控制器冻结即可。系统因此可以分层开发、分层复用。

### 3.5 为什么"只执行一次"的约束下系统仍然成立?

把 3.1–3.4 串起来就是答案:

- 生成端(查表+精修)把"哪些姿势物理上可行且横跨分支"这个问题**离线化**了——表是预计算的;
- 选择端把"哪个姿势能活到最后"压缩进一次网络前向——训练时的 54 万次执行,以网络权重的形式**摊销**给了部署时的每个任务;
- 执行端不需要在线适配(3.4),一次 rollout 就是最终答案。

三段各自把昂贵的东西挪到离线,部署路径上只剩:查表(毫秒)→ 前向(毫秒)→ 一次执行。

## 第四部分:踩过的坑(负结果清单,都有数据)

| 看似合理的做法 | 实际结果 | 教训 |
|---|---|---|
| 把表聚类压缩省内存 | 天花板 −23mm | 聚类中心是人造姿势;KD-tree 根本不怕 20 万条 |
| 直接回归一个种子(不要候选集) | 比候选+选择低 ~100mm | 分支选择被隐式化后学不动;该方法后来自己演化出"多专家+门控"=变相回到候选+选择 |
| 几何评分挑候选 | 比瞎选还差 | 见 3.2 |
| 挑选器没把握时退回保底姿势 | 受损任务反而从 37%→50% | 保底本身弱;没有强锚点的弃权=换个方式输 |
| 给控制器做适配训练 | 三次独立实验全部为零 | 见 3.4 |
| 表项挂历史成绩当先验 | 秩相关 0.089 | 成绩不在近邻粒度上迁移 |

这些负结果与正结果同等重要——论文附录 A 完整发表了它们。

```bash
cd /home/lqin/one && export PYTHONPATH=/home/lqin/one
PY=/home/lqin/miniconda3/envs/one/bin/python
```

## 一页总结

> 机械臂能画多远,开画前选哪个起手分支就定了大半;分支好坏开局看不出来、又不许试。
> 本系统:**IKSel 姿势字典**把"找出所有可行分支"离线化(查表+定向精修,1/3 算力顶穷举);
> **成绩单教学**把"预判谁活得久"压进一次网络前向(几何直觉全军覆没,完整执行回报是唯一有效监督,且天花板≈2/3 被测定);
> **混合控制器**执行且无需适配(任务相对观测+海量随机任务已提前吸收分布漂移)。
> 部署:查表 → 一次前向 → 一个姿势 → 一次执行。
